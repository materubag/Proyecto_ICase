# Pendientes técnicos y límites

- **Integraciones externas:** verificar transcripción y mockups con los workflows n8n reales del usuario, además de respuestas en vivo de Ollama/GPT. Las pruebas automatizadas de contrato usan un servidor local explícito. No se alteraron los workflows externos.
- **Modelado semántico:** la generación automática reutiliza detectores locales y requisitos funcionales; no interpreta todavía relaciones UML, atributos, cardinalidades ni despliegue mediante LLM. Esos datos se introducen como candidatos manuales con evidencia. Las entidades no se crean como tablas de PostgreSQL del sistema analizado.
- **Mermaid en servidor:** la validación y el intento de render ocurren en el navegador antes de habilitar aprobación. La API confía en `renderedSuccessfully` enviado por ese cliente; incorporar un renderer de servidor si se requiere verificar también consumidores REST arbitrarios.
- **Regeneración:** disponible por requisitos y artefactos seleccionados. Modelos manuales desactualizados requieren revisión explícita. No hay un job persistente que regenere automáticamente una cola de muchos artefactos. Los enlaces históricos se mantienen de forma conservadora y pueden ampliar el impacto respecto de las dependencias de la última versión.
- **Cambios:** UPDATE/DELETE/RESTORE están implementados para requisitos; los modelos soportan actualización/desactivación y revisión. CREATE utiliza las bandejas de candidatos, no un ChangeRequest separado en DRAFT. No existe historial independiente para cada campo de un modelo; se conserva en ChangeRequest, baselines y snapshots de artefactos. El proyecto previo no tiene usuarios/autenticación: no se atribuye una aprobación a una identidad inexistente.
- **Plataforma:** la selección del proyecto es una preferencia confirmada directamente. Los cambios de plataforma global no generan todavía un ChangeRequest ni invalidan automáticamente mockups existentes; regenerarlos explícitamente. Los cambios en nodos aprobados sí usan control de impacto.
- **Migración heredada:** los modelos antiguos quedan PENDING_REVIEW y se revisan desde Modelado con requisitos aprobados. Las pantallas antiguas permanecen en Screen y en la exportación; no se convierten automáticamente en mockups aprobados ni en ArtifactVersion. Hacer una importación revisada si deben incorporarse al historial nuevo.
- **Chat:** recuperación por palabras/códigos, evidencia e impacto; consulta local o proveedor seleccionado. No tiene conversación persistente multivuelta ni búsqueda semántica avanzada. Las propuestas de cambio sí se guardan como fuentes/candidatos.
- **UI:** formularios de modelado y comparación estructural básica. Edición UML avanzada mediante JSON; sin editor gráfico de relaciones. JSON exporta el estado completo; Markdown exporta principalmente requisitos.
- **Prueba histórica PDF:** falta `AUTRON_Propuesta_Overleaf.pdf`. No se afirma que esa suite específica haya pasado. El flujo PDF nuevo sí se prueba con un documento de fixture autocontenido.
- **Operación:** se mantiene `prisma db push`, como en el proyecto original. Antes de adopción productiva, establecer migraciones SQL y política de backups. No se ejecutan `reset` ni `--accept-data-loss`.
